# M45.2：來源欄位要能正確傳遞，不能因合法單字而拒絕

接續 M45.1 新 Web 的失敗：已知內容仍出現 invalid_exact_user_source_anchor，
日文任務另有 invalid_object_jp。原始候選只有 digest，不能斷言每次都是哪個字。
只讀檢查已確認兩個可獨立重現的契約缺口：source_id/source_span 是任意字串，
模型可拼错冗餘 metadata；「本」「紙」這樣的一個漢字會被結構檢查一律拒絕。

最小修復不降低語意審核門檻、不改原分句授權與 persona 策略：

1. 第二個呼叫的來源 ID 與原文引用，在解碼 schema 中限制為當輪允許的來源。
   引用只允許完整、原封不動的來源子句；仍作 source ID/quote 一致性檢查。
   多來源若指向不同來源仍走原唯一匹配規則。不是把評測答案写入模型。
2. 僅放寬合法的一字漢字 object 的格式限制；必須真的出現在最後建議中。
   語意相關性、具體動作、未知條件、風險、自然日文與實用性仍需原檢查全部過關。
3. 保留原 2 呼叫／18 秒預算。長來源可能因完整引用耗時或 token cap 而失敗，
   不能偷偷截斷來源，不能把語意 false 改成 true。
4. M45/M45.1 原始程式及 Safari 結果封存。完成原驗收後才啟用新 overlay，
   新契約測動態 schema、不修改原 schema、單字 object、未實現動詞／空泛步驟。
   另用新隔離 Safari 測缺任務→不學錯與中英日具體任務，所有失敗照實保留。

這是同一交付部件的格式修復，不另宣稱新的認知能力或全面理解。
