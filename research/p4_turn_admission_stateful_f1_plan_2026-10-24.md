# P4 stateful admission f1：一次隔離真 Safari 產品驗收的事前規格

狀態：**source-only 事前凍結**；題本是作者開發診斷，不是正式 holdout 或人評。先將本計畫、題本、preimplementation SHA 和任務卡提交推送到既有 PR #435、核 exact head，才准本題真模型或 Safari Send。`research/p4_turn_admission_post_f0_design_review_2026-10-24.md` 是此設計的邊界。f0 永久是 pre-Send strict FAIL；不重判、不重送、不清原 root。f1 的明示行動 cue 與舊 d/e/f 結構同屬 target route，事件主題不同；這仍是開發測試，不是語義獨立的 generalization claim。

## 問題、單一產品狀態與固定資源

本題只問：現有 code 在實際 stateful 背景流程下，能否對一個真 Safari 使用者輪產生完整、無交錯的 arrival→Brain snapshot→cognition→server terminal 歸因，並交付符合明示需求的可見回覆／原生圖／隔離 writeback？**不測 pristine tick0 等價，也不做同模型 LLM 對照。**不改 Brain、planner、回覆、背景 scheduler、journal/schema、UI、controller、正式 DB 或既有 gold。唯一新產品資料是 `datasets/p4_turn_admission_stateful_f1_probe_2026-10-24.json` 的一個題目與事前 gate。允許追蹤檔：本計畫、題本、preimplementation SHA、必要的 f1 零模型 focused test、一次結果報告、`CURRENT_TASK.md`。若 source/test go/no-go 失敗，不送 Safari；若要改方案另作事前設計，不覆寫本題。

固定本地 `qwen2.5:7b` digest `845dbda0ea48ed749caafd9e6037047aa19acfcfd82e704d7ca97d631a0b697e`、product control arm、原 product generation options、官方 ONNX digest `913d7300ceae3b2dbc2c50d1de4baacab4be7b9380491c27fab7418616a16ec3`、新 0700 私有 root、未佔用 7928、`--turn-admission-journal` opt-in、一次 Safari Send／0 retry。上限：3 completed **Brain user-turn** generations、2,000 provider tokens、20 秒 user wait；背景 ledger 另列。現有 `_product_compute_receipt` 在 `_run_turn` 內結算，隨後 Web status/delivery 可再查 Chroma，**此 f1 不具獨立的 delivery 向量 ledger**。因此額外 Web delivery 成本一律標 `unknown/not measured`，不可偷算為0；本題若其他 gate 過，只能 narrow PASS「admission＋可見品質＋Brain-turn 成本」，完整 runtime/production 成本 gate 仍 pending，不能稱 full product PASS。若 Brain-turn token/latency 帳也缺，f1 strict FAIL。只用 localhost，不付費、不外部部署。正式 private memory、原始 dirty checkout、無關 output 不碰。

## 檢查順序與 hard gates

1. 事前逐字搜尋 d/e/f 與舊 dataset，f1 原話碰撞必須 0；用現有 classifier、fake LeftBrain／真 RightBrain 的完整 `run_turn_debug` **零真模型**檢查：M29 `brief_encouragement`、M33 `not_applicable`、M18 未接管、M21 `full_planner` 且 compact 完成、scene support、direct_chat_answer、final＝episode。fake 結果只作 route go/no-go，不作自然度、persona 或真模型品質證據。任何 route/假 client 失敗先停。
2. 新 root 先 `prepare`、私有官方 ONNX 封網預熱及無 journal 的零對話 rehearsal，確認 same-final-PID HTTP ready、planned stop、port vacant。正式 opt-in run 也須同一 final PID、session/reset0、active `memory_db`、無其他 listener、模型 digest 同上。首次 listener readiness 暫時競態可在**同 PID**複查，不能換 PID 假稱 ready。
3. 正式 same-PID ready 後立即保存 T0 DB regular-file tree 的相對路徑／size／SHA-256 與取樣 monotonic 前後界線；Send 前保存 Tpre 同一 tree／界線，拒絕 symlink、root 外路徑或取樣中漂移，兩份 byte tree 必須相等。Tpre receipt 要同 PID/session/reset0/DB、brain ready、`human_submission_finish_count=0`、已知非負 tick；user episode/profile 為0。tick>0 可接受但必須作為**先前背景影響可能存在**寫入結果，不准稱 tick0。Tpre 到實際 Safari Send action 目標 ≤10 秒；沒有可核時序則 time gate unknown，產品 strict FAIL。
4. 到 Tpre 為止的 journal 可有**完整、事前已發生**的 `background_start/end` pair，第一筆不要求 arrival。逐 row 核 raw-free、連續 sequence、同 PID/session/reset/DB、start/end 同 ID、來源範圍是這兩種 event 而非不存在的 `source` 欄；pair 的 ledger attributed/coverage complete、no error/unknown independent worker、方法層 vector mutation returned/error 均0，指紋完整。任何 in-flight、缺 pair、unknown writer、DB tree drift 即不 Send。`passive_decay` 若改 memory/psyche 指紋仍可進行本題，但必須揭露 pre-state 與可能影響，不宣稱 pristine 或全域持久無寫入。
5. 只由原生 Safari 新 tab 發 f1 一次；Send 前在 UI 確認 exact source、session 和未送狀態。取 Tpre monotonic 樣本後若任何 background start/end 落於取樣不確定窗口至 server-arrival 之間，或無法判明先後，該題 strict FAIL（即使 Send 已發生也不重送）。arrival row 只須 browser source、同 opaque submission ID/PID/session/reset；其 `active_db_path`/tick 按現有 schema 是 null，**不可假填**。`admission_snapshot` 起核真 DB/tick/fingerprints；同 ID `cognition_start`、`cognition_end(status=completed)`、`terminal(status=delivered)` 必須連續、無 invalid/error/timeout、無背景或 proactive 交錯、無獨立 worker、state drift。`delivered` 是 server generator 完成，不是 Safari DOM ACK；真正 bubble 另驗。
6. 可見品質：短而自然日文，承接「庭の雑草を抜き終えた」這個可觀察進展，交付明示的一句鼓勵，不臆測睡眠／疲倦／私密感受／未說過的生活事，不轉成建議或追問；公開 persona 邊界內，且沒有錯誤身分聲稱。此題沒有詢問身分，**不能正向證明「她知道自己是うるは」**。泡泡＝私有 raw＝guard final＝graph utterance＝隔離 episode；Safari 原生 runtime graph 至少能核 user signal、retrieval、decision、utterance、writeback 的同輪內容／連線，不用 HTML replay 代替，保留可重核 PNG/AX 或同等原生視覺證據。若實際 selected core 已含 `。！？`，應無 `！。`／`？。`／`。。`、guard 無因此 fallback、final 保留 core；未觸發則標 `not_exercised`，不重送追標點。
7. 分層核帳：Brain user-turn actual model generation/prompt/completion tokens、wait、vector ops 必須完整且在上限內；另報 background pair/read/generative counts、journal bytes/events、isolated DB episode/profile 前後及完整性。Web delivery 額外 vector ops 如無獨立可核收據，明標 `unknown/not measured`，不得算0或宣稱全 runtime 成本已證。缺 Brain-turn 成本、source、圖或 final 一致性即 f1 strict FAIL。若 UI 工具拒絕，Web 保持 pending，不繞過；停 exact PID，驗 port vacant，只關新 tab，保留私有原件 hash。

## 結果與停止規則

若本題 narrow PASS，只代表這**一輪** stateful admission、可見品質與 Brain-turn 成本 hard gates 同時成立；Web delivery 額外 vector ops 仍 unknown，所以**完整 runtime/production 成本和 full product PASS 仍 pending**。任何 f1 hard gate 缺失標 FAIL/unknown，不以低層 0-call PASS 或 server `delivered` 代替 Safari。源題只送一次，不補送近似題追分；需修正時先讀原件、指出單一原因，最多兩批有根據介入仍失敗則 `REVIEW_REQUIRED`。正式同模型強 LLM 公平比較、真人被理解感、temporal holdout、跨 session 長期記憶、VRM＋Function Calling 的統一產品驗收與完整 Goal 均不由本題放行。
