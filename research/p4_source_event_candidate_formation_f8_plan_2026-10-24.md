# P4：來源事件進入 compact 候選形成（f8 前瞻設計）

狀態：**source-only design freeze；0 f8 generation／0 Safari Send／0 產品改碼**。此項沿用同一 P4 交付，不另算一個 M。f7a–d 的題、gold、結果與私有原件不改；f7d 已在真 Safari 證明可見錯誤：User 說 `初めて自分でハーブの苗を植えた`，候選核心與最終句卻說 `種をまいた`。f7 排序面對 3 個未獲來源證書的候選時無可排序，`no_grounded_candidate`，所以首個可觀測瓶頸是候選**形成**，不是排序參數。f7d 是已曝光反例，不能用作 f8 的新產品 confirmation。

## 單一變因、邊界與可反駁預測

只在 `control + M29 direct brief_care/brief_encouragement + M33 not-applicable + f7 utility on + full M21 compact`、且既有 f7 的 same-turn handoff/有限日文 User 自述事件語法驗證通過時，為 **compact 候選生成 prompt** 加短的來源事件約束：User 本人、是否 `初めて`、原文的 `object を completed_action`；三個候選各自要自然回答請求，同時不能把物件、動作、完成時態或行為者換掉。這是將當輪來源證據送進候選生成，不是加測題答案、固定回覆或修改記憶。事件關係長度 **>20 個 Unicode 字元** 時保守不注入，為 32 字 `core_message_jp` 留下首次／本人與簡短回應的空間；此閾值是工程可表達性界線，不是語義理解證明。來源屬引述、第三者、否定、多句、跨語、模糊句時亦 **不注入**；沒有聲學或私人心理證據就不補。

對照條件 f8 off／treatment f8 on **只比較 M21 候選形成**：從同一個未進行 User turn 的隔離初始 `memory_data`／psyche／same-turn validated handoff 建立兩個相互獨立的 LeftBrain；兩 arm 使用完全相同的序列化初始輸入與 memory/hash，不啟動背景 tick、不共享可寫 DB 或 episode。使用同一 qwen2.5:7b digest、persona、User input、f7 utility、compact JSON schema、temperature、max output、硬體與 token/時間上限；唯一處理是 opt-in 的 compact prompt source-event 段。若兩 arm 初始序列化狀態或除該段外的 request 不相同，配對比較作廢，不能靠事後重排補救。模型未固定 sampling seed 時單一配對只能是診斷，不能宣稱穩定因果效應或強 LLM 比較。flag off 的 request bytes／result 路徑需與現行 f7 byte-equal。不能全域改 `_FORMAT` 讓 off arm 也變，不能改模型、候選 schema、Bayes 權重、f7 certificate、M39、guard、surface、gold 或輸入。f8 on 可以在同一 compact transport 的條件分支把來源約束放在最後的格式說明之後，以消除現行 `do not repeat user's input` 與「必須保留原事件關係」的歧義；只禁止照抄整個求助問題，不禁止用來源事件短語回答。Raw prompt/私人對話不落 trace；只記 flag、輸入／事件 hash、注入結果與原因、原始候選 hash／有限 coverage、選擇／final hash、provider tokens/latency。

允許改動：新增純函式來源約束模組與焦點測試；`uruha_compact_planner_p2.py` 的 opt-in request 變換；`uruha_brain_mac.py` 在同輪 validated handoff→M21 compact 的窄接線；`p4_direct_reply_act_m29_priority_detached_control.py` 的 child-only opt-in flag/env；既有 runtime graph 只延伸必要 receipt。必要時對測試入口做最小接線。不得碰原始 checkout、正式 DB、人格資料、凍結 f7a–d 或無關 `output/`。這是產品 prompt conditioning，**不能**稱為通用理解、記憶因果、強 LLM 優勢或人腦方程式。

## 事前資料與判準

`datasets/p4_source_event_candidate_formation_f8_probe_2026-10-24.json` 為 developer-authored、source-disjoint 診斷，非獨立 holdout。新正例「自己第一次拍下夜空的星＋一句鼓勵」作唯一 M21 off/on 配對；另一個已**預先寫定**的「自己第一次讀山區地圖」只供條件式 Safari confirmation，不得看到配對結果後換題。f4–f7d 已曝光的味噌汁、鈕扣縫製、陶器小皿、庭椅、木小箱、短曲、香草苗物件／行為不重送；這仍共用「首次自己做＋一句鼓勵」結構，所以不是獨立研究 holdout。另有首次／非首次、exact 20／21 Unicode 字元邊界的契約例；非首次正例必須驗注入內容**不**發明 `初めて`，20 字可進、21 字必須拒絕。反例也涵蓋第三者、引述、否定、多句、非日文及較長事件；不得讓不合格來源改 prompt。M21 配對的事前可見 gold：短自然日文、承接第一次**自己拍下夜空的星**並給一個低壓鼓勵；改成「畫了星星／只是看見星星」、泛稱、教程、追問、混語、捏造或未請求催促均 FAIL。正例不能靠輸出包含「星」一字就判通過；必須核 actor／完成動作／物件／首次與使用者要求。f7 的 `grounded` 只驗窄 object-action 關係，不能替代完整 visible gold。

先跑 0-call source-only M29/M33/f7 grammar/HEAD 重用檢查，再凍結本計畫、資料與 SHA；此後不得看 output 改 gold。單元與契約先證明：off byte-equal；on 僅合法來源注入且 32 字界線安全；負例一律 off；同一候選三段仍由真模型生成，不偽造；無 grounded 時保留 `strict FAIL` 診斷，不讓 M21 generic fallback 冒稱語義修好。焦點命令應為 `.venv/product_checks/bin/python -m pytest -q test_compact_planner_p2.py test_p4_source_event_core_utility_f7.py test_p4_source_event_core_utility_f7_route.py test_p4_source_event_core_utility_f7_route_negative.py` 加新增 f8 tests，然後受影響 P4 回歸；不重跑無關長套件。

驗收先 fresh **planner-boundary** opt-in 配對對照，各 arm 單次 no-retry、留完整 3 候選真模型原文於**私有**可稽核原件（repo 僅 hash/有限摘要）、計算所有 coverage 與成本；它不能代替 full product、背景 admission 或同模型強 LLM 比較。事前定義每 arm `pass`：**M21 已完成、沒有 fallback 或 planner revision、所選原始 core 與 final core 同 hash**，其 f7 coverage `grounded`，且人工依凍結 gold 核其自然短日文、User 自己第一次拍下夜星、適度鼓勵，未改事件／混語／捏造；「三候選中有一個 grounded」不足以 pass。配對四結果：off fail/on pass = **狹義診斷改善**；兩者 pass = **parity、未證增益**；兩者 fail = **失敗**；off pass/on fail = **退步**。只有 on-only-pass 才放行**另一個事前固定的 source-disjoint 題**單次原生 Safari；其他分支保存結果、停止或回到設計審查，不在同題調 prompt。Safari 須保存 PNG/AX + runtime graph `input→retrieval→candidate/source evidence→decision→utterance→writeback`、Web泡泡/JSONL/episode 一致，核不污染正式長期記憶。與 f7d 一樣用互不重用的新 0700 root、private ONNX warm、Brain/DB/admission ready、Tpre→arrival ≤10s、0 背景交錯、1 Send/0 retry、exact stop；不重用非空 admission journal。
