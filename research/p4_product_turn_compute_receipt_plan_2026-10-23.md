# P4 product turn compute receipt: prospective plan

Date: 2026-10-23. Evidence class: product engineering / developer-authored probe, not formal holdout. The previously locked h0–h3 result remains narrow 4/4 and full-product strict FAIL. It will not be regenerated or rescored.

## Before and single variable

The h0–h3 native Safari receipt has response latency but no full-pipeline model/token ledger. In the current product Web path, `RuntimeManager.get_brain()` constructs `UruhaBrainV4_Mac()` without its existing optional `compute_ledger`; `_run_turn` does not enter a ledger item scope. The existing ledger already instruments OpenAI-compatible chat, M31 native Ollama, local Transformers generation and Chroma operations. This item changes **only product-Web attachment and turn attribution of that existing compute ledger**. It does not change model, prompt, decoding, memory retrieval, candidate selection, final language guard, persona, source rules, data or baseline.

Allowed code: additive `snapshot_item` on `uruha_compute_ledger.py`; optional product-only ledger attachment and per-turn receipt in `uruha_web_ui.py` and `uruha_web_ui_product.py`; new focused tests. The normal research entrypoints and uninstrumented Web path must retain their behavior. No change to frozen historical result, h0–h3 dataset, original dirty checkout or formal DB.

## Required contract

1. Product opt-in must attach the ledger **before** the first `get_brain`/prewarm; importing ordinary/research Web must not enable it. Every human text turn receives a collision-resistant item ID before `run_turn_debug`; all instrumented calls during that turn are attributed to exactly that item. Background or cold-start calls remain separately marked, never silently charged to the human turn. Include terminal/failed provider attempts with their available usage and error type; if the entire turn raises, retain a raw-free terminal error receipt in the private root when possible, then re-raise, never silently convert it to a successful reply.
2. A receipt contains per-backend/stage call counts, actual provider prompt/completion tokens where available, summed operation latency, Chroma operation and embedding-expected counts, and explicit coverage flags. Do not call Chroma operation count an embedding token count; do not call text-turn coverage speech/TTS, startup, OS resource or energy coverage. A zero-call turn reports **instrumented scoped generative calls = 0**, not full resource cost 0. Keep prompt/reply raw text out of the receipt. If a worker thread loses contextvars and emits an unscoped generative call during the human turn, attribution fails rather than reporting complete coverage.
3. For a successful turn, `receipt.item_id == private JSONL item_id == graph card item_id`; the receipt is tied to that runtime result and visible utterance. Persist full hash/length-bearing receipt **only** in an owner-only directory with a 0600 single-link regular file; if that privacy check fails, persist no full receipt and mark the durable-cost gate unavailable. The node graph shows only a concise cost/evidence card from the same receipt; no separate synthetic graph. A terminal error has no visible utterance and must not be counted as a successful turn. Receipt failure must remain visible as unavailable, not become a fake zero.
4. Uninstrumented Web and frozen P3 ledger schema/calls retain existing behavior. Attaching after the brain has initialized must fail closed or explicitly return unavailable, not invent zero. `snapshot_item` copies only matching calls under lock; long-session ledger growth remains an unresolved product resource risk, not production-ready accounting. Test with deterministic fake brain/clients, including two turns, zero-call, failed call, background/unscoped distinction, unsafe log directory, and no raw prompt/reply leakage. Compare visible reply, source/guard/history/episode fields before and after on the same fake turn. Then run affected regression and an isolated real product text turn.

## Independent prospective product probe

`datasets/p4_product_turn_compute_receipt_probe_2026-10-23.json` freezes two new source-disjoint cases before any model output. They test cost attribution and source-role delivery, not the broad human-response equation. Each case gets a **different launcher-created 0700 root and new product process**; a new Safari session or tab alone does not isolate memory because `URUHA_WEB_SESSION_DB_PATH` is process/root scoped. Maximum: two cases, one prompt each/zero retries, at most one zero-turn preflight and one product process per root, zero downloads. Zero-turn readiness may restart within one case root; the next case must never reuse that root. Verify distinct canonical root paths, T0 empty memory/session collections, one sent prompt/0 retry, no cross-case selected episode, exactly one private JSONL row and episode per root, `item_id` three-way join, final Japanese/guard/utterance/episode alignment, native graph cost node, and ≤20 s user wait. If the second root sees any first-case episode or an unscoped turn-time generation, the isolation/accounting gate fails. Record startup/prewarm cost separately from response cost. Exact prompt, response, ledger ID/usage and root checks are retained only as private evidence or summarized without raw private trace in Git.

The native Safari screenshot/AX tool currently has no documented local-save API. A live visual observation does **not** pass the saved-native-visual gate; no reconstructed HTML/graph substitutes for it. If this remains unavailable, the whole teacher-demo gate remains strict FAIL even if cost and isolation pass. Generative token coverage only counts instrumented providers that report usage; embedding tokens, audio/TTS, startup/background, CPU/RSS/energy and total production cost remain separately pending. This is not a same-model baseline, human evaluation, formal temporal holdout or general semantic understanding claim.

Stop on isolation/path uncertainty, missing attribution for an observed provider call, raw text in receipt, output/guard/history regression, wrong source role, UI/model error, >20 s, or missing graph/episode. Preserve the first failure, do not resend the failed case to improve a score. At most two causal correction batches under the existing workflow.
