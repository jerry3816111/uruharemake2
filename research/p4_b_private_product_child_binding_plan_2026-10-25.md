# P4 B 私有端點真正接入產品 child：下一批前瞻設計

狀態：**跨模型只讀設計審查已放行下批 0-provider 機械接線；尚未實作，B no Send。** 前批 `190bd93` 只讓 `UruhaBrainV4_Mac` 可在 opt-in constructor 連已驗證私有 endpoint；現行 Web/controller 不使用它。本批唯一核心變因是「隔離產品 child 的所有 Ollama 請求目標由共用 11434 改為同一 run-bound 私有 daemon」，不改 A/B 題、gold、人格、P2 request transformer、baseline、token/等待閾值、正式 DB 或一般產品預設。即使本批全過，B 的真 prompt-token 上界、M21 terminal 與 Safari deadline 仍須另審，不能 Send。

## 修改前證據

- `p4_preference_fallback_detached_control.py:576–674` 沒有 B opt-in；`run_id` 在約 630 才產生，638–640 的 product preflight 會先由 subprocess 匯入 Web，642–643 又把 launcher env 與 `_isolated_env` key 取交集，會丟棄新 B flag。controller 的 ready/stop PID 契約以固定 `ENTRYPOINT` 為準，不能隨便改啟動檔。
- 固定 entry `uruha_web_ui_product_p4_preference_fallback.py` 一開始就匯入 `_prior`；base `uruha_web_ui.py:731–733` 在 import 建 log dir，`RUNTIME=RuntimeManager()` 約 1605 隨即建 bare `ComputeLedger()`（765–768）、起 idle thread、寫 active-DB receipt（816–817）。`get_brain()`（850–870）只傳 bare ledger 或完全走 default constructor。因此只在 `get_brain` 補 URL 太晚，B 意圖缺件可以先造成 Web side effect，且目前真 child 仍共用 11434。
- `uruha_compute_ledger.py:626–655` 的 inner completion proxy 於 P2 轉換後看到真 request，但現在只做 B resource gate，沒有送前 private daemon/runner/model/receipt 再驗。M21 的 `except Exception` 仍可能吞 gate denial 成 fallback，Web 可在 final audit 前 stream 角色片段；這兩項不在本批變動，不准藉 endpoint 接線放行 Send。

## 單一變因、具體設計與順序

1. Controller 增加**顯式參數** `p4_b_private` 與 private model root／daemon+runner PID/port／run descriptor；不可只因 parent env 含某 flag 自動進 B。default/inert/A 行為逐欄保留。B branch 在既有 prepared product root 與 `run_id` 產生後、任何 Web import/preflight/Popen 前，驗專屬 0700 model root、檔案／程序／listener/env 與 child 預期隔離 DB/log layout；一個失敗即 terminal，不嘗試共用 11434。model root 一個 run 專用，不復用失敗 root。允許 prepared-root claim 等既有記錄先發生；不可把它說成 no-side-effect transaction。
2. B branch 改為**不匯入 Web 的靜態 preflight**：核 Python、sandbox、cache、layout與已提交來源 SHA，保持既有 final `ENTRYPOINT` 與 ready/stop PID 命令契約；原 product path 仍走既有 import preflight。controller 在 static preflight 後、Popen 前簽 0600 run-bound launch receipt 至 private model root，且再驗 live identity。這需要**前瞻 receipt schema v2**：除 model/service 身份，還綁 canonical final Popen env 的 B＋隔離 key 白名單 SHA、固定 entrypoint 源碼 SHA、expected argv SHA、產品 runtime root/run ID；在 child bootstrap 重新計算並比對。固定 entrypoint 與 boot／binding 關鍵來源 SHA 必須在 static preflight、緊貼 Popen 前及 child boot（任何 Web import 前）三處相同；drift 拒絕。白名單精確包含 B marker、run/root/receipt、隔離 DB/log、`URUHA_WEB_COMPUTE_LEDGER=1`、`URUHA_P4_COMPACT_JSON_SCHEMA=1`、`OLLAMA_NO_CLOUD=1`，並排除／拒絕 proxy env 覆寫；不能經舊交集靜默丟失。啟動前還不知道 child PID，故 controller 的啟動後／ready 原子紀錄另綁實際 PID、argv、listener、同一 run/receipt digest；B Send 必須等 ready 核過，不能以 launch receipt 假稱已核 child。metadata 只留必要 ID/hash/非敏感欄，不留 raw env 或對話。

   精確 B-only env 證書欄位：`URUHA_P4_B_PRIVATE_CHILD=1`、`URUHA_P4_B_RUN_ID=<run_id>`、`URUHA_P4_B_MODEL_ROOT=<canonical 0700 root>`、`URUHA_P4_B_RECEIPT=<exact 0600 path>`、`URUHA_WEB_COMPUTE_LEDGER=1`、`URUHA_P4_COMPACT_JSON_SCHEMA=1`、`OLLAMA_NO_CLOUD=1`；另把既有 `_isolated_env` 的 `HOME/TMPDIR/URUHA_MEMORY_DB_PATH/URUHA_WEB_SESSION_DB_PATH/URUHA_WEB_LOG_JSONL_PATH/URUHA_WEB_LOG_TXT_PATH/URUHA_WEB_HOST/URUHA_WEB_PORT` 各 exact value 納入 canonical hash。拒絕 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 等代理 key（大小寫同樣）；無關 inherited env 不形成 B 權限。固定 env 名稱為計畫候選，設計審查可修但實作後不能無紀錄改義。
3. 固定產品 entry 第一個可能有副作用的匯入之前，B-only bootstrap 依 controller marker＋run/root/receipt 驗 binding，建立唯一常閉 `P4BResourceGate`＋同一 `ComputeLedger` 的 boot state；有 B marker 但缺一項必須在 log dir／RuntimeManager／DB 前拒絕。`uruha_web_ui.RuntimeManager` 在 import-time 只取已驗 boot state 的 ledger，`get_brain` 只在該狀態明確傳 `p4_b_private_mode=True`、同一 binding/run/ledger；pointer identity 不符或 B 意圖沒有 boot state 則拒絕，不退 default。沒有 B marker時 base/product入口完全沿舊路。
4. 在 P2 compact 後、真 OpenAI create 前，B-only inner chokepoint 除既有 gate 外，重驗同一 binding 的程序啟動代次、listener owner、private model files、daemon env、receipt 與 endpoint，漂移即阻止 provider 請求。**現有 M21 仍可能吞此錯誤產生 fallback；本批不宣稱可見終止安全，也不做 B Send。** 首批 receipt validator 的 60 秒值是我們的接縫工程值，非 A/B 凍結門檻；本批擬以**前瞻 receipt schema v2** 明示改成 B diagnostic-only 最長 300 秒：`issued`／`expires` 必須是有限數值且非 bool，`now−300 <= issued <= now+2`、`issued < expires <= issued+300`、`now < expires`，bootstrap 與每次 create 均同規則，沒有自動續租。controller 僅在 static preflight 完成後、緊貼 Popen 時發行。測試必須覆蓋 60 秒舊版拒絕、300 秒新版兩側邊界、cold/prewarm 實測耗時、檢查中過期或 receipt 被撤銷；若超時或使用者等待耗盡時窗，拒絕 provider、root 不復用且不按 B Send。不能事後延長、把開機驗證代替送前證據，或宣稱這已是通用產品生命週期。

允許檔案候選：`p4_preference_fallback_detached_control.py`、固定產品 entry、`uruha_web_ui.py` 的 import-time boot state／`RuntimeManager`／`get_brain` 窄接線、`uruha_compute_ledger.py` inner chokepoint、新 B-only bootstrap/identity 小模組、已提交 binding module 的明示 TTL/recheck 小修與新聚焦測試。**只放行這份清單的 0-provider 機械接線**；如 controller/entrypoint/ready/stop 需擴改，先修本設計，不以 broad refactor 混入。`uruha_brain_mac.py`、P2 transformer、source/gold、正式 DB、Web stream/deadline、A runner及凍結研究入口不在本批許可。

## 驗收與停損

- 先 0-provider fake child 紅／綠：before 捕捉 env 被丟、Web bare ledger、11434 target；after 要見 controller 最終 env→產品匯入前 boot→Web 同 ledger/gate→brain opt-in→實 SDK fake transport 的**同一私有** `/v1/models`，P2 轉換後 fake create 在 gate 常閉下 0 provider completion。假的 static preflight 需以 import sentinel 證明完全不載入 `uruha_web_ui` 或固定產品 entry；壞 marker／缺 binding 要在 log mkdir、RuntimeManager/idle thread/active-DB receipt、DB 與 Popen 前拒絕。錯 flag/run/root/receipt/env/port/model/PID generation、listener owner 在開機前被拒；開機後漂移在 provider create 前被拒，兩者分開計數。B 無設定不得因繼承環境誤啟；default/原 A launcher、ready/stop 身分與 DB/log 路徑逐欄不變。
- 先小測→controller/Web/ledger/constructor 相鄰回歸→必要時新隔離、非 B 句真產品 zero-turn 同 PID ready/stop，逐層分證。計入讀 4.68GB GGUF 兩次的 wall/bytes、metadata calls、CPU/RSS、child cold prewarm；本批 0 真 completion，因此**沒有 provider token usage parity 或真對話等待**可報，不能用首批單次 2.507202s 代替全程成本。上限：**0 A/B 真問題、0 B Safari Send、0 真 completion、0 正式 DB**；非 B 真 provider usage parity 另凍結最多一次的資源卡再做，不夾在本批。
- 本批不更動 M21 exception、Web partial/late-result、20 秒 client click→DOM；因此就算 child 路由全過仍只稱 endpoint delivery 機械證據，B 繼續 `REVIEW_REQUIRED`。B Send 的後續同時前置：A 作者三項評分＋外部 receipt、真 A on-only final gold PASS、B transformed request 同身份真 token bound＋同 shape 非 B provider parity、唯一 M21/0其他生成、terminal fail-closed／晚到角色句不能覆寫、非 B 原生 Safari 零 provider queue/lock/stall 演練與同域 click→DOM 20 秒證據；最後 B 自身才准唯一真 Send。見原 `research/p4_b_hard_cap_presend_review_2026-10-25.md`。失敗保留反例，至多兩個有根據修正批，不重用 A/B 題追分。
