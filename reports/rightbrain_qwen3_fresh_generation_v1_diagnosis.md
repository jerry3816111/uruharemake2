# Qwen3 fresh-generation 失敗診斷

## 結論

64-step 更新會穩定改變未見 prompt 的文字，但沒有改善已達滿分的語意與表面契約，並使目標人格與中性條件較難區分。因此本輪不授權保存 adapter、人格訓練或正式上線。

## 已觀察事實

| 指標 | 更新前 | 更新後 | 差值 |
|---|---:|---:|---:|
| joint contract | 8/8（100%） | 8/8（100%） | 0 pp |
| semantic complete | 8/8（100%） | 8/8（100%） | 0 pp |
| provider pair difference | 3/4（75%） | 2/4（50%） | -25 pp |
| reference bigram F1 | 0.405392 | 0.394570 | -0.010822 |
| 實際改變的回答 | - | 3/8 | - |

三次隔離重跑的更新前輸出、更新後輸出、最終參數及 optimizer state 雜湊分別完全一致。這表示上述結果不是 temperature 或單次抽樣波動。

## 可見失敗案例

條件是同一個「曾談過桌遊，向新參加者自我介紹」情境，只改 persona provider。

| 條件 | 更新前 | 更新後 |
|---|---|---|
| 目標公開人格 | 前に話したボードゲーム好きで、一緒遊んでみない？よろしく！ | 不變 |
| 中性人格 | 前に話したボードゲーム好きで、一緒遊んでみませんか？よろしく！ | 前に話したボードゲーム好きで、一緒遊んでみない？よろしく！ |

更新後，中性人格回答與目標公開人格完全相同。語意仍正確，但 provider 條件對表達方式的控制消失了一部分。

## 證據邊界

本輪可以證明：

- 64-step 更新的 loss 降低能轉移成可重現的文字變化。
- 文字變化不等於品質提升。
- 在這八題中，增加相同訓練步數造成 persona provider 區分度退步。

本輪不能證明：

- 所有未見情境都會發生人格滲漏。
- 根因一定是資料量、LoRA、模型大小或 Prompt。
- 目標人格本身已被正確學會。

## 下一個可推翻假設

目前的 token-level answer loss 主要獎勵兩種 provider 共同的語意與句型，沒有直接懲罰「中性條件生成目標人格句型」。下一輪應固定模型、資料來源、更新次數與生成題，只將訓練目標改成 provider-conditioned pairwise contrastive objective，檢查能否避免條件崩塌；不應直接增加 epoch。
