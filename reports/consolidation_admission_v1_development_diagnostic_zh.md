# 記憶鞏固准入 V1：負面結果診斷

## 這次真正測了什麼

同一個 `qwen2.5:7b` 對 18 組新多輪對話各跑兩種契約，共 36 次成功呼叫：

| 條件 | 只改變的部分 |
|---|---|
| 現行直接規則契約 | 使用目前 session-turn 背景鞏固 prompt，直接產生 wisdom 與 procedural 規則 |
| 來源綁定候選 | 先標示記憶種類、範圍、對象與完整原句，再由固定程式決定能否寫入 |

這不是完整 runtime 測試，沒有執行 heuristic fallback、Chroma 寫入、回憶或實際聊天。

## 凍結結果

| 指標 | 現行契約 | 來源綁定候選 |
|---|---:|---:|
| 正確分類 | 0/18 | 6/18 |
| wisdom | 0/6 | 0/6 |
| procedural | 0/6 | 0/6 |
| 只留 episodic | 0/6 | 6/6 |
| JSON/schema 成功 | 18/18 | 11/18 |
| 中位延遲 | 4.743 秒 | 5.376 秒 |
| warm p95 | 6.004 秒 | 7.591 秒 |

候選結果：錯誤長期寫入 0，但漏掉應寫入案例 12。所有預註冊門檻整體 **FAIL**。

## 為什麼失敗

1. **現行契約過度抽象。** 16/18 同時產生 wisdom 與 procedural，另外 2/18 產生 procedural；它沒有真正的「不寫入」准入層。
2. **候選契約對模型太複雜。** 7/18 把數值 `confidence` 回成文字 `"high"`，因此 schema 失敗。
3. **模型混淆說話者。** 在 11 個 schema 可解析案例中，5 個引用了助理句子或不存在的改寫句，而不是完整 User 原句。
4. **候選只學會保守，沒有學會選擇。** deterministic compiler 最後把 18/18 都判為不寫入，所以能擋住一次性事件，卻完全失去長期記憶召回率。
5. **速度也未達標。** 候選中位與 warm p95 都超過預註冊上限。

## 可以與不能下的結論

可以說：目前 session-turn 直接規則 prompt 在這批開發題中會過度產生長期規則；本次來源綁定契約能避免錯寫，但無法保留應寫內容，因此不能上線。

不能說：完整 UruhaBrain 的實際錯寫率是 100%、此結果能代表所有對話、或軟體已實作人類的生物記憶。

## 停損與後續方向

- 同一批 18 題不得重測，也不放寬 parser 重新計分。
- 正式背景鞏固維持原狀；本輪不授權 runtime shadow 或 Chroma 寫入。
- 下一個新實驗應使用全新 session，並把工作拆開：固定程式先保留 User 原句與說話者，模型只判斷 `target/scope`，通過准入後才生成日文規則。這是新假設，不是本輪結果。
