# 記憶鞏固准入 V2：負面結果診斷

## 本輪修改的能力

本輪只測「短期對話是否應進入長期記憶」。同一個 `qwen2.5:7b`
處理 18 組全新三輪對話，每組各跑一次 V1 JSON 對照與 V2
索引工具候選，共 36 次呼叫。

V2 不再要求模型重抄證據原句或生成日文規則。程式保留 User
回合編號，模型只輸出記憶種類、範圍、適用對象及證據回合。

這不是正式聊天、Chroma 寫入、回憶或人類相似度測試。

## 凍結結果

| 指標 | V1 JSON 對照 | V2 索引工具 |
|---|---:|---:|
| 正確分類 | 6/18（33.33%） | 8/18（44.44%） |
| wisdom | 0/6 | 2/6 |
| procedural | 0/6 | 0/6 |
| 只留 episodic | 6/6 | 6/6 |
| 可解析輸出 | 9/18 | 15/18 |
| 索引契約成功 | 不適用 | 13/18 |
| 完整 frame 正確 | 不適用 | 1/18 |
| 正向案例證據正確 | 不適用 | 8/12 |
| 錯誤長期寫入 | 不適用 | 0 |
| 漏掉應寫入案例 | 不適用 | 10 |
| 中位延遲 | 5.135 秒 | 2.853 秒 |
| warm p95 | 7.117 秒 | 3.038 秒 |

V2 比對照多答對 2 題、沒有退步題，格式與速度也改善；但預註冊要求
至少答對 16/18、procedural 至少 5/6、漏寫最多 1 題，因此整體
**FAIL**。

## 失敗發生在哪裡

1. **索引輸出有幫助。** V2 的可解析率由 50.00% 提升到 83.33%，
   正向案例中有 8/12 選到允許的 User 證據，延遲也約減半。
2. **`owner` 定義混淆。** 6 個 procedural 題中，模型 6/6 都輸出
   `memory_kind=procedural`，但全部把 `owner` 填成 `user`。目前契約
   想問「這條記憶約束誰」，模型卻理解成「證據由誰說」。
3. **compiler 正確地拒絕了歧義 frame。** procedural 必須約束
   assistant；因此上述 6 題雖辨識出程序性內容，最後仍 fail closed
   為 `none`，沒有把來源不明的規則寫入。
4. **wisdom 仍被過度程序化。** 6 題中只有 2 題成功，另外多數被
   分成 procedural，表示「使用者穩定特徵」與「未來應答方法」仍未
   被模型可靠拆開。
5. **none 的表面滿分不能單獨採信。** 6/6 最終都為 `none`，但部分
   是格式失敗或 compiler 擋下未授權 frame；frame 與證據門檻因此
   沒有通過。

## 可以下的結論

把來源文字改成固定回合索引，確實改善格式、證據選取與速度；但把
`owner` 同時當成來源與規則適用對象，會讓模型在 procedural 記憶上
系統性失敗。這個版本不能進入正式 runtime，也不能證明人類式記憶。

## 停損

- 不在這 18 組資料上修改 prompt、parser、compiler 或門檻後重測。
- 不啟用 runtime shadow、Chroma 寫入或日文規則生成。
- 正式聊天系統保持原狀。
- 下一個可否證假設必須使用全新 session，並把「證據來源」與
  「規則適用對象」拆成不同欄位；可由程式根據記憶種類決定適用對象，
  不再要求模型重複推斷已知結構。
