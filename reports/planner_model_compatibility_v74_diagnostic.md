# V74 左腦模型替換相容性檢查

## 結論

**Qwen3.5 4B 與 9B 都不直接替換目前左腦。**

這一輪完全保留原本的完整三候選規劃、BDI 欄位、自我檢查與正規化，只替換本機模型。目的是排除 V73 的「縮短流程」問題，確認換新模型本身是否能同時改善速度與品質。

## 同一輸入、同一完整契約

| 本機模型 | 時間 | 輸出 tokens | 結構 | 主要問題 | 決定 |
|---|---:|---:|---:|---|---|
| Qwen2.5 7B | 51.8 秒 | 1,300 | 3 候選 | BDI 中文、固定尾句 | 現況對照 |
| Qwen3.5 4B | 22.3 秒 | 647 | 3 候選 | 使用「俺」、邀請實體喝酒、BDI 遺失 | 淘汰 |
| Qwen3.5 9B | 58.0 秒 | 1,113 | 3 候選 | 使用「私」、比 7B 更慢 | 淘汰 |

使用的探索句是「午後の予定が急に空いた。まだ何をするか決めてない。」；它不會進入未來正式 holdout。

## 為什麼不能只看官方分數

Qwen3.5 官方模型卡顯示 9B 的指令遵循與 agent 能力通常高於 4B，也提供 function calling 與非思考模式。但本機完整認知契約會要求長 JSON、三個候選和多個心理欄位，實際成本與一般 benchmark 不同。

官方資料讓 Qwen3.5 有「值得測」的理由，這次本機結果則決定它「目前不能直接換」。

## 傳輸問題已排除

OpenAI 相容 API 最初讓 4B 消耗 2,504 tokens 卻回傳空內容，因此不能直接判成模型失敗。改用 Ollama 原生 API 並明確設定 `think=false` 後，4B 與 9B 都能產生可解析 JSON；最後淘汰理由來自實際語意、人格與延遲，而不是傳輸錯誤。

## 證據邊界

這只是正式實驗前的一題相容性篩選，不是模型準確率，也不能證明 Qwen3.5 整體比 Qwen2.5 差。因為沒有候選同時通過基本速度與品質條件，所以沒有建立正式預註冊、沒有擴大題數、沒有修改 runtime。

下一步不再直接試更多模型。應先確認現有資料是否足以訓練一個專門輸出完整 speech plan 的本機規劃器；資料不足就先補資料，不直接微調。
