# RightBrain AdamW 首步裁切效果診斷：無效結果分析

## 結論

本次診斷依事前規則判為 **invalid**，不能用來判斷梯度裁切對 AdamW
第一步是否有實質影響。

同一模型、同一 adapter、同一 seed、同一 8 筆資料與同一 loss 計算下，
本次重建的梯度 norm 為 `2.878972`，先前鎖定結果則為 `403.728180`。
相對誤差為 `99.2869%`，遠超事前允許的 `0.1%`。因此自變變因「是否
裁切」尚未成立，任何 clipped／unclipped 模擬差異都不能解讀。

## 完整性檢查

| 項目 | 結果 |
|---|---:|
| 8 筆 row ID | 8/8 相同 |
| 8 筆 loss | 8/8 與先前結果逐值相同 |
| 先前梯度 norm | 403.728180 |
| 本次梯度 norm | 2.878972 |
| 梯度 norm 相對誤差 | 99.2869% |
| 允許誤差 | 0.1% |
| 有 gradient 的參數張量 | 392/392 |
| 權重 SHA-256 前後 | 完全相同 |
| optimizer step | 0 |
| 模型儲存／正式 runtime 修改 | 0／0 |

這表示資料順序、forward loss、gradient coverage 與權重完整性都通過，
但 backward 梯度尺度沒有重現。

## 不可解讀的數字

本次程式仍依 `2.878972` 計算出裁切係數 `0.104204`，並得到 clipped 與
unclipped 假想更新的相對 L2 差 `33.18%`。這些數字只描述這次未通過
完整性檢查的梯度，**不是有效的裁切效果結果**，不得用來調高 max_norm、
修改 learning rate 或重新訓練。

## 目前可以主張

- 第一輪 `403.728180` 梯度 norm 尚未被獨立重現。
- 同一批 forward loss 相同，不足以保證 backward 梯度尺度相同。
- 在梯度重現性釐清前，不能把上一輪訓練失敗歸因於裁切或 AdamW。

## 目前不能主張

- 裁切對 AdamW 第一步有或沒有實質影響。
- `403.728180` 或 `2.878972` 哪一個才是穩定的真實尺度。
- MPS、gradient checkpointing、LoRA dropout 或量測函式中的任何一項
  已被證明是根本原因。

## 下一個可推翻假設

使用單一、事前鎖定的 gradient-only harness，在彼此隔離的新 Python
process 中重複重建完全相同的 8 筆 backward，記錄總 norm、逐 LoRA 側與
逐 projection norm。若各次結果無法落在事前誤差範圍內，便確認目前訓練
路徑存在 backward 重現性問題；若結果穩定集中於其中一個尺度，才進一步
檢查另一個執行與量測路徑。下一步仍不得建立 optimizer 或更新模型。
