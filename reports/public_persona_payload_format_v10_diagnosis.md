# 公開人格 Payload Format V10 負面結果診斷

## 結論

V10 沒有通過。把完全相同的左腦 payload 從 compact JSON 改成分行欄位，
沒有讓 `qwen3.5:9b` 更完整地實現既有計畫，反而遺失更多角色與核心語意。

## 實際差異

| 指標 | compact JSON | 分行欄位 | 差異 |
|---|---:|---:|---:|
| 角色槽命中 | 35/36 | 31/36 | -4 |
| 角色完整案例 | 14/15 | 10/15 | -4 |
| 核心語意通過 | 18/20 | 16/20 | -2 |
| V4 人格通過 | 12/15 | 10/15 | -2 |
| 表面 gate 通過 | 14/20 | 15/20 | +1 |
| 具體性通過 | 11/12 | 12/12 | +1 |
| 中位延遲 | 3.598 秒 | 3.880 秒 | +0.282 秒 |

分行欄位沒有新增任何角色槽，也沒有新增任何角色完整案例。原本完整的四個案例反而退步：

- `persona_v3_fatigue_02`：失去目前狀態。
- `persona_v3_health_02`：失去明確的不確定性。
- `persona_v3_health_03`：失去有根據的目前狀態，並造成核心語意退步。
- `persona_v3_notice_03`：失去開始訊號，並造成核心語意退步。

V9 指出的 `persona_v3_notice_01` 入口角色在兩個條件下都仍然缺失，因此 V10
沒有解決原始問題。分行欄位雖讓少數表面或具體性 gate 變好，但無法抵銷角色、
語意與人格的退步。

## 被推翻的假設

目前模型不是只因 compact JSON 太難讀，才沒有把左腦計畫完整說出來。同一份資訊改成
分行文字後更差，表示問題更可能在計畫到語句的對齊與實現機制，而不是單純的序列化外觀。

依預註冊決策，本結果禁止再次微調或重跑同一種序列化方法，除非先取得新的獨立證據。

## 證據完整性與邊界

- 20/20 配對的 canonical payload 完全相同，40/40 表示完整性通過。
- 模型、digest、系統提示、seed、sampling 與輸出預算固定。
- transport error、工具呼叫、產品記憶寫入與 VRM 實體動作都是 0。
- V2 holdout 沒有開封，runtime、模型、scorer 與訓練都沒有修改。

本結果只排除目前 `qwen3.5:9b`、目前 canonical payload 與 frozen V31 mixed-lines
serializer 的組合。它不能排除所有可讀介面設計，也不能證明人格忠實度或正式聊天品質。
