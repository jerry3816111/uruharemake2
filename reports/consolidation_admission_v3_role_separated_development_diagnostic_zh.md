# 記憶鞏固准入 V3：負面結果診斷

## 本輪修改的能力

本輪測「短期對話是否應進入長期記憶」。同一個 `qwen2.5:7b`
處理 18 組全新三輪對話，每組各跑一次 V2 索引工具對照與 V3
角色分離候選，共 36 次呼叫。

V3 將證據來源固定為程式保存的 User 回合，並由記憶種類推導適用對象：

- `wisdom` 適用於使用者資料。
- `procedural` 適用於助理未來行為。
- `none` 不進入長期記憶。

模型只判斷記憶種類、長期依據和證據回合。這不是正式聊天、Chroma
寫入、回憶或人類相似度測試。

## 凍結結果

| 指標 | V2 索引工具對照 | V3 角色分離 |
|---|---:|---:|
| 正確分類 | 9/18（50.00%） | 10/18（55.56%） |
| wisdom | 5/6 | 3/6 |
| procedural | 0/6 | 2/6 |
| 只留 episodic | 4/6 | 5/6 |
| 可解析輸出 | 18/18 | 14/18 |
| 索引契約成功 | 15/18 | 12/18 |
| 完整語義 frame 正確 | 不適用 | 7/18 |
| 正向案例證據正確 | 不適用 | 8/12 |
| 錯誤長期寫入 | 不適用 | 1 |
| 漏掉應寫入案例 | 不適用 | 6 |
| 中位延遲 | 2.845 秒 | 2.396 秒 |
| warm p95 | 2.963 秒 | 2.532 秒 |

V3 新答對 3 題，但讓原本答對的 2 題退步，淨增只有 1 題。預註冊要求
至少 16/18、每類至少 5/6、淨增至少 4 題且退步最多 1 題，因此整體
**FAIL**。

## 失敗發生在哪裡

1. **角色分離修正了一部分 procedural。** 6 個 procedural 題的原始
   `memory_kind` 全部判成 procedural，不再因 `owner=user` 全數被拒絕。
2. **長期依據仍不穩。** 其中 4/6 把明確的未來回覆規則判成
   `repeated_pattern`，而不是 `explicit_future_policy`，所以 compiler
   只接受 2/6。
3. **欄位仍會互相污染。** 2 題把 `stable_trait` 填進
   `memory_kind`，顯示模型會把記憶種類與持久依據混在一起。
4. **工具傳輸沒有更可靠。** 2 題沒有產生 tool call；另有 2 個
   `none` 題仍選了證據回合，候選解析率只有 14/18、索引契約 12/18。
5. **wisdom 付出退步代價。** 對照組答對的兩個 repeated wisdom
   在 V3 變成格式失敗，造成 2 個 regression。
6. **速度改善不足以補償判斷錯誤。** 中位延遲下降約 0.45 秒，但
   正確率只淨增 1 題，沒有達到可上線的效果。

## 可以下的結論

把證據來源與適用對象移出模型是正確的架構方向，也讓 procedural
不再因角色欄位全數失敗；但同一個 Qwen2.5 7B 在單次 tool call
中仍無法穩定分開記憶種類與持久依據，格式可靠度也下降。這個版本
不能進入正式 runtime。

## 停損與下一條工作線

- 不在這 18 組資料上修改 prompt、schema、parser、compiler 或門檻重測。
- 不啟用 runtime shadow、Chroma 寫入或日文規則生成。
- 正式聊天系統保持原狀。
- 停止「同一 Qwen2.5 7B 單次 tool call，只繼續縮減 frame」的路線。
- 下一輪應使用全新資料，比較兩個真正不同的假設：
  1. 兩階段決策：先判斷 `write/none`，再對 write 分類
     `wisdom/procedural` 與證據。
  2. 換用另一個可在本機執行、工具參數約束更穩定的模型。

只有新方案在相同控制條件下明顯提高正向召回、降低退步並保持安全，
才值得進入後續整合。
