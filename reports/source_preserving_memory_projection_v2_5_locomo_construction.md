# V2.5 LoCoMo Fresh Holdout 建構結果

**決策：`construction_invalid_oracle_do_not_run_model`**

## 先驗門檻

模型尚未執行。建構器必須先證明答案真的存在於對話正文，再檢查投影是否保留該原文。

| 指標 | 事前門檻 | 實際 |
|---|---:|---:|
| 正文含答案的有效 case | 12/12 | 9/12 |
| 正文投影保留答案 | 至少 10/12 | 4/12 |
| Manifest 舊判定 | 不適用 | 7/12 |
| 平均保留字元 | 至多 50% | 19.4% |
| 模型呼叫 | 只有建構通過才 48 次 | 0 |

## 原因

原建構器把時間戳與說話者標籤一起拿去搜尋答案，造成 3 題假通過。剩下 9 題中，Top-3 字面重疊又有 5 題沒有選到真正含答案的 turn。這是資料 oracle 與記憶投影問題，不是 9B 模型能力不足。

建構 oracle 無效的 case：

- `locomo-v2-5-conv-48-44`
- `locomo-v2-5-conv-30-20`
- `locomo-v2-5-conv-30-35`

正文有效但投影遺失答案的 case：

- `locomo-v2-5-conv-50-57`
- `locomo-v2-5-conv-30-11`
- `locomo-v2-5-conv-49-41`
- `locomo-v2-5-conv-49-52`
- `locomo-v2-5-conv-49-4`

## 邊界與下一步

這四段 holdout 已用來診斷 top-3 字面投影，不能重新包裝成新測試。下一版只能更換一般化投影方法，並只使用原先保留的六段 reserve 對話重新預註冊。

本結果沒有測模型、沒有修改 runtime、沒有寫入記憶，也沒有啟動 VRM。
