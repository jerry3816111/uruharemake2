# 公開人格條件契約 V3 負面結果診斷

## 結論

V3 條件式人格契約會改變模型輸出，但沒有提高預先定義的人格策略通過率，並增加延遲與兩筆敬語漂移。因此本輪失敗，不啟用正式聊天、不開封 holdout、不訓練模型。

| 觀察 | 控制組 | 條件式契約組 | 判讀 |
|---|---:|---:|---|
| 核心語意通過 | 18/20（90.0%） | 18/20（90.0%） | 無能力增益，也無語意退步 |
| 人格策略通過 | 10/15（66.7%） | 10/15（66.7%） | 沒有新增通過案例 |
| 表面品質 gate | 17/20（85.0%） | 15/20（75.0%） | 新增 2 筆敬語漂移 |
| 適用情境回答改變 | - | 14/15（93.3%） | 模型確實讀到 carrier |
| 非適用情境完全一致 | - | 5/5（100%） | 開關邊界正確 |
| 中位延遲 | 3.338 秒 | 4.080 秒 | 增加 0.742 秒（約 22.2%） |

## 可以排除什麼

- 不是「條件契約完全沒有進入模型」：15 個適用情境有 14 個回答改變。
- 不是記憶、動作或 Function Calling 污染：20/20 protected fields 相同，工具呼叫、記憶寫入與實體動作都是 0。
- 不是測試傳輸失敗：40/40 呼叫完成，transport error 為 0。

## 尚不能分開的兩個原因

### 1. Carrier 的表達方式不夠有效

條件式 brief 使用抽象的英文 policy 值。模型雖然有反應，但沒有把規則穩定轉成自然日文；`health_02` 與 `health_03` 反而從非敬語變成敬語，`delay_01` 還出現 Markdown 粗體、emoji 與內容順序倒置。

### 2. Scorer 與契約有不一致

- 自我介紹契約是「最多一次輕微自我調侃」，scorer 卻要求一定命中 `だら／ぐだ／適当／寝`，把可選行為當成必須行為，影響 3 題。
- `delay_01` 的 marker 接受 `今さら` 與 `見て`，但順序判斷只接受字面 `遅` 在 `楽し` 前；語意可接受的替代表達仍可能被判失敗。

因此目前不能只根據 66.7% 判定本機模型不夠聰明，也不能根據 14/15 輸出改變宣稱人格改善。

## 下一個可推翻假設

先建立「契約與 scorer 語意一致性稽核」，把必須、可選、禁止、順序等規則用同一份機器可讀契約產生，並用人工可判讀的最小正例、反例與同義改寫驗證。只有評測能正確區分這些案例後，才比較自然日文 carrier、現有抽象 carrier 與靜態控制組。
