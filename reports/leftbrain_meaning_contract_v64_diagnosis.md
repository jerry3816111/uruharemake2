# V64 左腦意義契約診斷

## 結論

只在目前的 `qwen2.5:7b` 左腦提示中增加「角色、命題、時間、記憶狀態與回覆義務」schema，**沒有讓回覆計畫更完整**。依預註冊規則，這個方法停止，不接右腦，也不修改正式聊天流程。

## 正式結果

| 指標 | 精簡計畫 | 結構化契約 | 差異 |
|---|---:|---:|---:|
| 必要意思命中 | 12/28（42.9%） | 11/28（39.3%） | -3.6pp |
| 整題完整 | 4/14（28.6%） | 3/14（21.4%） | -1 題 |
| 禁止意思違反 | 0/14 | 0/14 | 相同 |
| JSON 與 schema 合法 | 14/14 | 14/14 | 都通過 |
| 角色關係命中 | 不適用 | 3/14（21.4%） | 未達 70% |
| 新舊記憶判定 | 不適用 | 3/4（75.0%） | 未達 100% |
| 中位延遲 | 4.77 秒 | 16.06 秒 | +11.29 秒 |
| P95 延遲 | 6.24 秒 | 20.22 秒 | +13.98 秒 |
| 峰值記憶體 | 約 5.04 GiB | 約 5.04 GiB | 通過限制 |

必要意思差異的 95% bootstrap 區間是 `-14.3pp` 到 `+7.1pp`，沒有支持正向改善。

## 失敗原因

1. **會填表不等於會推理。** 14 題都產生合法 JSON，但命題內容常不正確。
2. **人物與視角仍會錯。** 「健太會送資料」的 frame 把健太寫成 `kenji`。
3. **事實與未知狀態仍會錯。** 澳洲首都被寫成不存在的「カンベイ」；沒有會議紀錄時仍把下午三點當成答案。
4. **社會不確定性沒有被保留。** 同事只回「あとで」時，計畫仍推成「也許在生氣」，沒有把截止日前忙碌當作替代解釋。
5. **記憶 schema 沒有保證完整使用。** 膝傷題只列出目前記憶，漏掉被取代的舊跑步偏好，因此 4 個新舊狀態只判對 3 個。
6. **成本明顯增加。** 結構化欄位讓中位延遲變成原本約 3.4 倍，但沒有換到語意增益。

## 評分限制

凍結 scorer 使用預先寫好的日文表面詞。有些語意合理的改寫沒有被算到，例如「個人チャットを見ることは不適切。直接話しかける」沒有命中較窄的拒絕與安全替代表面詞。因此 `39.3%` 是**凍結自動評分器下的數字**，不能當成完整的人類語意正確率。

依研究規則，結果產生後不能補詞、改答案或重跑同一批題目。這個限制不會把失敗改成成功：結構化組仍沒有顯示穩定優於精簡組，而且延遲大幅增加。

## 對專案的實際意義

- 已排除「只要給舊 7B 左腦更長、更結構化的 JSON schema，就會自然變聰明」這條路。
- 正式右腦與聊天流程保持不變，因此沒有引入退步。
- 下一個值得驗證的問題不是再加欄位，而是：在相同通用契約下，較新的本機模型是否能正確填入角色、事實、不確定性與記憶狀態；這必須使用全新資料與較不依賴固定表面詞的預註冊評分方法。

一句話總結：**問題不是模型不會輸出 JSON，而是目前 7B 左腦沒有穩定填入正確的認知內容。**
