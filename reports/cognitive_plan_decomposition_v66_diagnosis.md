# V66 認知責任分解診斷

## 結論

把 Qwen3.5 4B 固定拆成「先選角色、證據與記憶，再選認知立場與行動」沒有比相同兩次呼叫的完整計畫重做更準。兩組都是 5/12 個完整計畫正確，因此本輪假設不成立，不修改正式聊天流程。

## 正式結果

| 條件 | 模型呼叫 | 完整計畫正確 | 8 欄位正確 | 中位延遲 | 峰值記憶體 |
|---|---:|---:|---:|---:|---:|
| 一次完整計畫（成本參考） | 1 次/題 | 4/12（33.3%） | 80/96（83.3%） | 6.62 秒 | 4.90 GiB |
| 兩次完整重做（配對控制） | 2 次/題 | 5/12（41.7%） | 80/96（83.3%） | 13.79 秒 | 5.59 GiB |
| 選擇→決策（責任分解） | 2 次/題 | 5/12（41.7%） | 83/96（86.5%） | 8.82 秒 | 5.46 GiB |

正式 run 完成 5 次暖機與 60 次正式模型呼叫，傳輸錯誤為 0。三組皆有 12/12 題通過所需工具解析；raw log 不含答案，正式 runtime 與記憶均未變更。

## 主要因果比較

主要比較只看兩個都使用兩次模型呼叫的條件：

- 責任分解新增答對 3 題，也讓原本答對的 3 題退步，淨增益為 0。
- 完整計畫正確率相同，都是 41.7%。
- 責任分解的欄位正確率高 3.2 個百分點，但沒有轉成更多整題正確。
- 責任分解中位延遲比兩次完整重做少約 36%，因為第二階段只讀被選中的內容，不再重讀全部 packet 與完整草稿。

所以本輪只能證明責任分解較省第二次推論成本，不能證明它較聰明。

## 答對交換

責任分解救回的 3 題：

1. 轉寄訊息中的「兄」屬於原訊息作者。
2. 手機剩 5% 且即將出示登機證時先省電。
3. 未經允許不能操作同事電腦，應直接向同事索取資料。

責任分解失去的 3 題：

1. 直接引語題多選了不必要的聽者證據。
2. 朋友醫療資料題把拒絕錯選為一般建議與保留不確定。
3. 「被星期一追趕」題把行動候選 ID 誤填進 response act。

每個能力群只有兩題，這些差異只能當成後續線索，不能據此寫死「哪些題型一定分解」。

## 未解決的穩定錯誤

- **記憶取捨：** 三個條件都在發燒時繼續啟用舊的長跑偏好，表示問題不是呼叫次數，而是「舊偏好何時應被當前限制壓制」尚未形成可靠機制。
- **認知不確定性：** 三個條件在兩題都未完整答對，常把支持、澄清、拒絕與認知立場混在一起。
- **欄位污染：** 模型有時把 decision target 的 ID 填入 response act；function-call 格式合法不代表值的語意角色正確。

## 對專案的實際意義

- 已排除「所有 planning packet 都固定拆成兩階段」作為充分解法。
- 證明精簡第二階段可降低本機延遲，但正確率不足，不能上線。
- 下一個優先問題不應是再增加分解層數，而是檢查正式記憶狀態如何表示「目前有效、已被現況壓制、私人不可說」，並用全新跨回合案例驗證記憶狀態轉換；這同時對真實對話與人類式記憶有直接價值。

## 證據邊界

這是 12 題全新內部 holdout，測的是 planning packet 已建好之後的精確計畫選擇。它不能證明完整聊天自然度、正式記憶檢索、右腦人格、公開 benchmark 成績或廣義人類相似度。

一句話總結：**固定分解讓第二次推論更快，但沒有更準；下一步應修記憶狀態機制，而不是繼續堆分解層。**
